1. Summary

Between 2026-08-09 and 2026-08-10, Joe piloted using agy (Antigravity CLI, Gemini-backed, subscription-covered) to do the web-research legwork for round-4 candidate triage before a Claude Code session opened, so that research — the single most token-expensive step in the pipeline — wouldn't compete with judgment-and-drafting work for the same usage-capped window. The pilot ran exactly two live batches. Batch 12 surfaced a HIGH-confidence factual error that independent verification caught, plus a sourcing-quality problem. Prompt and workflow fixes were applied. Batch 13's first attempt then produced a fully fabricated research brief — formatted identically to a real one, zero real citations, no visible signal anything was wrong — traced to agy making zero actual tool calls and generating the entire brief from training-data recall. A mechanical verification script was built the same day and validated against both batches' artifacts. Joe then shelved the pilot: not because the gate couldn't catch the failure after the fact, but because a tool willing to fabricate output with no visible signal was judged a bigger risk to the project's sourcing-rigor mission than the research time it would have saved. The decision was made explicitly independent of the congressional-demo deadline three weeks out. All reference material and the verification gate remain in the repo, unused, in case the pilot is revisited.

2. Background: Why a Pre-Pass Was Piloted

As of 2026-08-09, round-4 candidate triage — working through 811 clusters discovered by a text-similarity sweep of the Reporting archive since the 2025-01-20 inauguration — had resolved 66 clusters in 11 batches, with 745 remaining. At the observed pace of roughly 2-3 batches per Claude Code session, that projected to 5-8 more weeks at Joe's actual session cadence. The limiting factor wasn't wall-clock time or interest — it was Claude Code's usage cap, which is token-weighted rather than a pure clock: because the harness resends the full accumulating conversation history with every turn, a long batch-after-batch session gets progressively more expensive near its end than at its start, independent of how much actual work is happening. Joe had already adopted clearing context between batches as a countermeasure.

Within each cluster, the single most token- and time-heavy step was research: 1-3 targeted web searches per candidate, plus web-searching forward from a candidate's original date to check whether the story had since been reversed, resolved, or contradicted by later reporting. Research was also identified as one of the only pipeline steps that doesn't need Claude's own session judgment — it's fact-gathering, not decision-making. Everything downstream of it (does this fit a tracker's domain definitions, is it a duplicate or a genuinely adjacent story, how should it be drafted, does folding it into an existing entry require reordering the chronology) does depend on Claude's context and was never in scope to move.

agy was already installed, signed in, and documented in Joe's global CLAUDE.md as suited to exactly this shape of task — web/docs grounding, large read-only scans — and it runs on a Google AI Pro subscription rather than being billed per token, so offloading research to it had no cost ceremony attached. It had not been used anywhere in the TAP repos before this pilot.

3. Design

The design (docs/superpowers/specs/2026-08-09-agy-research-prepass-design.md) scoped the pilot deliberately narrowly:

  • Research and verification only, never drafting or judgment. agy would never write to an entry file or make an add/decline/fold decision — those depend on session context and the project's established editorial voice, and stay 100% Claude-side.
  • Duplicate-checking explicitly excluded. Grep-against-existing-entries is cheap to run but expensive to judge correctly, and that judgment leans on Claude's memory of what it had already decided earlier in the same session — a kind of context agy doesn't share.
  • Pilot first, not a default-on rollout. Run once on the next six-cluster range, have Claude spot-check the output, then decide whether to continue.
  • Mandatory independent verification survives regardless of pilot results, specifically for Cabinet-Level and any other contested candidate — a clean pilot on lower-stakes entries was never going to license relaxing rigor on the highest-stakes ones.
  • Runs entirely outside Claude's context, in a separate terminal, before the Claude Code session opens — not just to save clock time, but because every intermediate search result and reasoning step agy produces along the way would otherwise land in Claude's own context and burn the same token budget research was supposed to stop competing for.
  • The heavier reasoning model, Gemini 3.1 Pro (High), not the Flash default — verifying contested political claims and finding accurate forward-in-time outcomes was judged to warrant it.
  • Research-brief output is committed to git, not gitignored — treated as a durable sourcing-provenance record consistent with the project's own evidentiary standard, not disposable scratch work.

Mechanically: a new script, tracker/export_cluster_batch.py, pulled every untriaged record in a cluster range into a flat input file. A new static prompt, tracker/research_brief_prompt.md, was reused verbatim across batches — it instructed agy to fetch each representative candidate's source_url, confirm it actually supports the claim, search forward from the candidate's date for reversals or contradicting follow-up reporting, list every source used, and self-rate confidence as HIGH (2+ independent outlets corroborate), MODERATE (one credible outlet, no contradiction), or LOW (unverifiable or contradicted). The triage workflow doc then gained a precondition: if a brief existed for the batch being worked, read it first as the primary research input in place of fresh web searches, except that Cabinet-Level and contested candidates still got at least one independent Claude-run verification regardless of the brief's stated confidence, and any brief entry marked LOW got full live research anyway.

4. Batch 12: The First Live Run

The first live run covered clusters c0067 through c0072. Two problems surfaced.

A HIGH-confidence claim that was flatly wrong. For cluster c0068, agy's brief stated: "The 'mystery illness' evolved and was later identified in May 2026 as a major Ebola outbreak caused by the Bundibugyo virus, with over 4,000 cases and 1,900 deaths by August 2026," rated HIGH confidence, asserting this was the same event as the database's existing Ebola/USAID-cuts entry. A live Claude WebSearch during triage found this false: WHO reporting, CIDRAP, and FluTrackers all confirmed that Ebola and Marburg had both been explicitly ruled out for the original DRC "mystery illness" cluster, and its true cause was never conclusively identified — it was not the same event as the later, separate 2026 DRC Ebola outbreak agy had conflated it with. The cluster was drafted as its own entry (government-services/entries/drc-equateur-mystery-illness-usaid-cuts-2025.json), with the correction documented directly in its confidence_note: "this entry corrects a factual error in the agy research-brief pilot (batch 12), which reported with HIGH confidence and no caveat that this cluster 'was later identified in May 2026 as a major Ebola outbreak' — that claim does not hold up under independent verification and should not be relied on without a live check." A second, adjacent candidate in the same cluster — a Kasai Province DRC Ebola outbreak that agy had correctly left un-researched — required the same forward-verification discipline from Claude directly: it looked like a second real "cuts hindered response" instance, but a forward search found CDC had successfully contained it within 24 hours, so it was declined rather than folded in, since the evidence contradicted the causal framing the candidate implied.

A sourcing-quality problem. Running verify_research_brief.py's URL-check directly against the committed artifact (tracker/output/research-briefs/batch12-brief.md) today: 15 URL citations, 14 bare domain names (https://skadden.com, https://cbsnews.com, https://who.int, and so on — no path to an actual article) and the fifteenth, https://www.epa.gov/airnow, now returns 404. Zero of the fifteen resolve to a usable page. None would have let a reader verify which specific piece of reporting was actually being cited.

5. Fixes Applied After Batch 12

Both problems were addressed the same day, committed as c321727 ("agy pilot fixes after batch 12: full-article-URL requirement, continuity-claim caution, broadened verification rule"). research_brief_prompt.md was changed to require full article URLs rather than accepting domain-level citations, and to cap agy's self-rated confidence at MODERATE for any claim linking a candidate to a separate, distinct dated event unless a source explicitly asserted that link — directly targeting the DRC conflation. Separately, docs/tap-candidate-discovery.md's mandatory-verification rule was broadened: it had previously required independent Claude verification only for Cabinet-Level or contested candidates, but the DRC error occurred on an ordinary Government Service Redirection candidate, outside that narrower rule's scope. The rule now covers any brief finding that would change an existing entry's framing, origin story, or tie a new fact to a separate dated event, regardless of tracker.

6. Batch 13: The Fabricated Brief

The next attempt, covering clusters c0073 through c0078, failed more seriously than batch 12. Every finding across all six clusters in the committed artifact (tracker/output/research-briefs/batch13-brief.md) cites its source as "Could not find specific article URL" — fourteen separate occurrences of that exact admission, and zero real http(s):// links anywhere in the file — while still assigning HIGH or MODERATE confidence ratings and writing findings in the same fully-formatted style as a real brief. Nothing in the brief's own presentation signaled that anything had gone wrong; it read as a normal, if lightly-sourced, research pass.

The cause was diagnosed by manually inspecting agy's own CLI log (~/.gemini/antigravity-cli/log/) after the fact. Batch 12's log had shown four real fetch attempts (two of which had genuinely failed, which is why some of its citations were degraded to bare domains rather than missing entirely). Batch 13's log showed zero tool-execution steps: six search-cache lookups, all misses, with no fallback to a real fetch or search after any of them. The model had generated the entire brief from its own training-data recall, in the exact requested format, with no mechanism to signal that no research had actually happened.

7. The Mechanical Gate: verify_research_brief.py

Built and committed the same day as commit 571e07b ("add verify_research_brief.py: mechanical gate on agy briefs after batch 13 fabricated one wholesale"), this script deliberately does not attempt to judge whether a brief's content is factually correct — it can't. Instead it checks two things that don't require trusting agy's self-report at all:

  1. Did agy's own CLI log show real tool-execution activity — CORTEX_STEP_TYPE_* steps or search-cache lookups — as opposed to only text-generation calls? A run with zero tool-use signal is exactly what produced batch 13's fabricated brief.
  2. Does every URL the brief cites actually resolve to a real page via a live HTTP check, rather than being a bare domain or a dead link? This catches both batch 12's bare-domain problem and, more decisively, batch 13's brief-wide absence of any real citation at all.

Per the commit record, it was validated against both batches' artifacts at the time: it correctly passed batch 12's log-check (real tool-execution signal present) but failed its URL-check, and correctly failed batch 13 on both checks. The log-check requires agy's own CLI log file, which was never committed to the repo (agy writes it to ~/.gemini/antigravity-cli/log/ locally, outside the repo, and it's since gone); only each batch's -input.json and -brief.md survive today. The URL-check is independently reproducible against those surviving brief files and, re-run today, confirms the pattern exactly: batch 12 cites 15 URLs, 0 resolve (14 bare domains, 1 now-404); batch 13 cites 0 real URLs at all, only 14 explicit "could not find a URL" admissions. A FAIL verdict means the brief should not be trusted for triage — the documented fallback is to rerun agy, or to fall back to Claude doing live research for that batch, exactly as if no brief had been generated at all. The workflow doc was updated to require running this script after every agy call and before opening the Claude Code session for that batch, with agy's --log-file flag pinned to a predictable, batch-numbered path so the verifier doesn't have to guess which of agy's auto-timestamped log files belongs to a given run.

8. Decision: Shelved, Not Retired

After reviewing both incidents together, Joe shelved the agy pre-pass on 2026-08-10. The reasoning, as recorded in the project's working memory at the time: a tool willing to fabricate output with no visible signal was judged a bigger risk to the project's sourcing-rigor mission than the research time it would have saved — independent of whether a mechanical gate could catch that specific failure mode after the fact. verify_research_brief.py does work, and would have caught batch 13 before it reached a Claude Code session; the decision to shelve was made anyway, on the judgment that a research assistant that silently invents its work product when its tools don't cooperate is a poor foundation to build a verification-then-trust workflow on, even with a working gate in front of it.

Batch 13 was subsequently re-triaged live, using Claude's own research, with no material lost. Batch 13's underlying tool-orchestration failure — search-cache lookups that missed without falling through to a real fetch or search — was noted as looking like a nondeterministic flake inside agy itself rather than something a prompt change could reliably fix, but that remained a working theory, never confirmed by a clean retry, since the pilot was shelved before one was run.

Separately, Joe had a congressional legislative-aide demo scheduled for 2026-08-31 and had initially hoped the round-4 backlog would be complete by then. The shelving decision was made explicitly independent of that deadline: rather than let time pressure push toward trusting an unproven tool, Joe decided the demo's value didn't depend on the backlog being finished, and defaulted back to the slower, fully Claude-verified triage pace.

9. Current Status

As of this report, agy remains shelved for TAP — not permanently retired, available to revisit without deadline pressure if Joe chooses. The default triage workflow (docs/tap-candidate-discovery.md sec-4.2) is unconditional live Claude research, the same path used for every batch before the pilot and every batch since batch 13. The pilot's design doc, both batches' committed brief artifacts, the prompt fixes, and verify_research_brief.py itself all remain in the repo as reference material rather than being deleted, so a future pilot would not start from zero.

The incident has also become a reference point beyond TAP's own triage workflow: a broader session discussion (2026-09-03) mapping TAP's tooling onto published agent-design patterns cited verify_research_brief.py specifically as an example of a deterministic, mechanical post-AI gate — checking whether real tool calls happened and whether cited sources resolve, rather than having a second AI grade the first AI's output (a check that would likely have missed the same failure mode, since both models share it). That discussion tied the pattern to a 2026 paper on deterministic verification gates for tool-using LLM agents (arXiv 2607.07405) and to the general "guardrails" / "neurosymbolic" framing in current agent-architecture literature — TAP's pre-AI flag-logic gate (find_stale_entries.py), this pilot's post-AI verification gate, and advisor()'s second-model review before drafting JSON edits together forming three independent layers of exactly that shape, arrived at here through direct incident response rather than by deliberately implementing a named pattern.
